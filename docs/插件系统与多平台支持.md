# Aluer ServerGuard 插件系统与多平台支持

本文档描述 ServerGuard 的两项核心能力：**插件系统**（第三方扩展）与 **多平台/多版本支持**。

---

## 一、插件系统

### 1. 概述

插件系统允许第三方开发者以独立 JAR 的形式扩展 ServerGuard 引擎能力，无需修改引擎源码。
插件被加载后，可通过 `PluginContext` 发布安全告警、注册命令、查找引擎服务 Bean。

### 2. 核心类型

| 类型 | 包路径 | 职责 |
| --- | --- | --- |
| `ServerGuardPlugin` | `com.aluer.pluginsystem` | 插件生命周期接口（onLoad/onEnable/onDisable） |
| `Plugin` | `com.aluer.pluginsystem` | 插件元数据注解（name/version/author/depends 等） |
| `PluginDescriptor` | `com.aluer.pluginsystem` | 插件描述符（不可变元数据） |
| `PluginManager` | `com.aluer.pluginsystem` | 发现/加载/启用/停用/卸载 |
| `PluginContext` | `com.aluer.pluginsystem` | 插件与引擎交互的上下文 |
| `PluginClassLoader` | `com.aluer.pluginsystem` | 插件隔离类加载器（父优先） |
| `PluginSystemService` | `com.aluer.pluginsystem` | Spring 集成引导 |

### 3. 插件开发

插件主类实现 `ServerGuardPlugin` 接口，并用 `@Plugin` 注解声明元数据：

```java
package com.example.myguard;

import com.aluer.pluginsystem.*;

@Plugin(name = "my-guard", version = "1.0.0", author = "example",
        description = "示例安全模块", depends = {})
public class MyGuardPlugin implements ServerGuardPlugin {

    private PluginContext context;

    @Override
    public void onLoad(PluginContext context) {
        this.context = context;
        context.getLogger().info("my-guard 加载中...");
        // 注册一条引擎命令
        context.registerCommand("myguard-scan", "扫描示例", args -> {
            context.getLogger().info("执行 myguard-scan，参数: " + String.join(" ", args));
            return "scan complete";
        });
    }

    @Override
    public void onEnable() {
        context.getLogger().info("my-guard 已启用");
    }

    @Override
    public void onDisable() {
        context.getLogger().info("my-guard 已停用");
    }
}
```

打包成 JAR 后，在 JAR 内放置 `META-INF/serverguard-plugin.properties`：

```properties
main=com.example.myguard.MyGuardPlugin
name=my-guard
version=1.0.0
author=example
description=示例安全模块
api-version=1.0
depends=
```

> 注：`main` 键为必填（用于定位主类）；其余元数据可省略，由 `@Plugin` 注解补齐。
> 若注解与 properties 同名字段冲突，注解优先。

### 4. 部署与配置

将插件 JAR 放入插件目录（默认 `serverguard/plugins/`），重启引擎即自动加载并启用。

```yaml
serverguard:
  plugin:
    enabled: true
    directory: ${SERVERGUARD_PLUGIN_DIR:serverguard/plugins}
```

- `enabled=false` 时跳过目录扫描，但插件系统 Bean 仍可用（便于程序化注册）。
- 插件按依赖顺序启用（`depends` 声明），依赖缺失的插件保持停用并记录警告。

### 5. 告警管道

插件通过 `context.publishAlert(AlertEvent)` 发布告警，告警会进入引擎统一告警管道
（`ServerGuardService.publishAlert`），享受与引擎内置检测一致的 AI 分析、邮件通知与自动处置。

## 二、多平台 / 多版本支持

### 1. 支持矩阵

| 平台族 | 平台 | Agent 运行方式 | 说明 |
| --- | --- | --- | --- |
| Bukkit 系 | Vanilla(CraftBukkit) / Spigot / Paper / Purpur / Pufferfish / Folia / Glowstone | 直接运行（plugin.yml） | 覆盖 1.12.2 至今全部版本 |
| 代理端 | BungeeCord / Waterfall / Velocity | 需独立适配器（见下文） | 引擎已具备类型识别能力 |
| 模组加载器 | Forge / NeoForge / Fabric / Sponge | 需独立适配器（见下文） | 引擎已具备类型识别能力 |

### 2. Bukkit 系跨版本原理

Bukkit/Spigot/Paper 的 API 在不同版本间存在差异，直接编译期调用部分方法会在旧版本
服务端抛出 `NoSuchMethodError`。因此引入 `com.aluer.platform` 包统一处理：

- `MinecraftVersion`：解析、比较版本号（`1.12.2` → `1.21.1`），支持 `isAtLeast` / `isSupported`。
- `PlatformType`：平台类型枚举（含 Bukkit 系、代理端、模组加载器）。
- `PlatformDetector`：运行时反射探测平台与版本。
- `BukkitCompat`：跨版本反射兼容层，收敛所有“版本敏感”调用：
  - `getPing`：`Player#getPing()` → `Player.Spigot#getPing()` → `0`
  - `kick`：`kick(Component)`（Adventure）→ `kickPlayer(String)` → `kick()`
  - `broadcast`：`broadcast(Component)` → `broadcastMessage(String)`
  - `getTps`：`Server#getTPS()` → `{20,20,20}`

`plugin.yml` 使用 `api-version: '1.12'` 并声明 `folia-supported: true`，
使同一 Agent JAR 可运行于 Spigot 1.12.2 至 Paper 1.21.x、Folia 等全部 Bukkit 系平台。

### 3. 代理端 / 模组加载器适配

代理端与模组加载器的插件 API 与 Bukkit 完全不同，需各自独立的入口与适配器。
引擎侧已通过 `PlatformDetector.detectFromClassName()` 识别这些平台类型，为适配器预留了能力上报。

- BungeeCord / Waterfall 入口描述符（`bungee.yml`）：

  ```yaml
  name: AluerServerGuard
  main: com.aluer.proxy.AluerBungeePlugin   # 需独立的 Bungee 适配器实现
  version: 5.2.0
  author: Aluer
  ```

- Velocity 入口描述符（`velocity-plugin.json`）：

  ```json
  {
    "id": "aluer-serverguard",
    "name": "AluerServerGuard",
    "version": "5.2.0",
    "main": "com.aluer.proxy.AluerVelocityPlugin"
  }
  ```

> 上述 `main` 指向的代理适配器需依赖 BungeeCord / Velocity API 单独编译，
> 属于独立子模块（本项目当前以 Bukkit 系 Agent 为主体）。

## 三、Agent 插件自动注入

ServerGuard 采用「外部引擎 + 游戏内 Agent」双体架构，传统部署需人工把 Agent JAR
复制到游戏服务器 `plugins/` 目录。引擎提供 `com.aluer.deploy.AgentDeployService`
在启动时自动完成注入。

**原理**：引擎产物是 Spring Boot fat jar，其类位于 `BOOT-INF/classes/` 下，Bukkit
插件类加载器只识别 jar 根目录的标准类结构，因此 fat jar 无法被服务器直接加载。
注入服务在运行时把 Agent 最小依赖闭包（`com.aluer.plugin / platform / agent / model` 包）
重新打包成标准结构的插件 JAR，写入服务端 `plugins/` 目录。Agent 依赖的 gson、
slf4j-api、Bukkit/Adventure API 均由服务器运行时提供，无需打包。

**配置**：

```yaml
serverguard:
  minecraft:
    working-dir: /opt/minecraft          # 服务端工作目录（含 plugins/ 子目录）
    auto-inject: true                    # 启动时自动注入（默认开启）
    agent-jar-name: serverguard-agent.jar
```

- `auto-inject=true` 时，引擎启动即把 `serverguard-agent.jar` 部署到 `workingDir/plugins/`。
- 仅做「复制 JAR」这一无损动作，不主动重启服务器；重启后插件即被加载。
- `working-dir` 不存在时仅记录日志，不影响引擎启动。
